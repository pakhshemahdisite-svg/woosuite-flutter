## Repository engineering and AI contribution standard (2026-11-14)
These requirements supplement existing project-specific rules.
- Work independently, precisely and honestly. Execute authorized reversible low-risk tasks; escalate material risks and access blockers.
- Check actual branch, commit and release before modifications; define acceptance criteria; use only needed specialist roles and disclose whether real independent review or parallel agents were available.
- Follow requirements, architecture, implementation, integration, review, security, relevant automated/functional/performance tests, documentation, packaging, staging and authorized release verification.
- Use modular code, least privilege, validation, secret protection, versioned migrations, backwards compatibility and rollback. Do not weaken existing controls.
- Record real changes and test evidence in GitHub; never claim unperformed tests, builds, deployments or agent activity. Distinguish design, implementation, testing and release.
- Control costs, seek approval for risky irreversible actions, and report actual actions, evidence, blockers, risks and next steps.
